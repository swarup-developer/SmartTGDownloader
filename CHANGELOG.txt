SmartTG Downloader Changelog
========================================================================
Version: 2.2.0 / 8.9.0
Build/Version Code: 6 / 8.9.0 (Android 2.2.0 / Windows 8.9.0)
Release Date: November 27, 2026
========================================================================

SUMMARY OF CHANGES:
Android 2.2.0 keeps downloads running after you leave the app, uses a strict
step-by-step download flow that hides finished steps, moves default file-type
filtering into Settings -> Analysis, and fixes large-channel scanning and
download cancellation edge cases. Windows 8.9.0 adds remembered/configurable
default filters, scan-mode progress controls, non-blocking update prompts, and
folder/file classification fixes.

[ADDED]
- Android: Settings -> Analysis now includes a Default file type selector (All /
  Audio / Video / Images / Docs), alongside "Ask which type before analyzing"
  and the default scan limit.
- Android: Home and the results sheet now follow a strict progressive flow:
  Step 1 (link input) and Step 2 (Analyze) collapse once a scan/download starts
  (with a "Change link" action), the results sheet keeps the file list collapsed
  by default behind a toggle, and each stage (Choose -> Range -> Confirm ->
  Downloading -> Finished) hides earlier controls and adds an in-app "Cancel
  download" action.
- Windows (8.9.0): added Default Content Filters, "Ask which filters before
  analyzing", and "Check for Updates" to Settings -> General; remembered filter
  selections across scans; and added live scan progress updates in the dialog
  (with Pause hidden during scanning).
- Windows (8.9.0): fixed photo/voice-note subfolder routing, sanitized Windows
  reserved channel folder names and trailing dots, fixed proxy validation
  blocking Settings saves when proxy is disabled, prevented the OTP resend timer
  from ticking after login, cleaned up 0-byte orphan files on aborted downloads,
  and replaced the update prompt's "Exit" action with "Later".

- Android: downloads now run in a foreground service with a progress
  notification, so a batch continues after leaving the app. The pending queue
  is persisted and resumes after a process restart, and TDLib's own cache
  resumes a partly downloaded file instead of refetching it.
- Android: download failure handling - each file is retried twice with backoff
  before being reported, with its reason and a Retry action on Home, in the
  results list, in the completion notification, and in History.
- Android: per-channel download preferences (file type, range, scan limit)
  keyed by the resolved Telegram chat id, with per-channel and forget-all
  controls in Settings.
- Android: range selection in the results panel by file number, plus Newest
  10/20/50/100 presets; the last applied range is remembered per channel.
- Android: a scan limit per channel (100 / 500 / 1,000 / 5,000 / All), with a
  Search deeper step offered both where a truncated scan is reported in the
  results list and in the empty state, labelled with the limit it will raise to
  ("Search deeper (1,000 files)", or "Search the whole channel" at the last
  step) so the cost of the next scan is on the button. A channel's own limit can
  also be set from its row in Settings - Channels, which is the only way in for a
  channel that has never been analyzed; the dialog offers the whole ladder, and
  offers a limit that is not on it alongside the steps rather than hiding it.
- Android: download connection choice (any connection, or Wi-Fi only), enforced
  before every download including retries.
- Android: OTP resend on Telegram's own escalating cooldown (30s / 50s / 60s).
- Android: unit tests (JUnit 4, JVM) for the preference precedence, range
  seeding and scan-limit escalation rules, for the history paging policy, and for
  the range combobox's label rule - the unset-range sentinel, an empty list, a
  remembered range clamped onto a smaller list, and the singular wording for a
  one-file range.
- Android: a folder per channel in Download/SmartTG Downloader/<channel>/, plus
  an Open Downloads folder action when a batch finishes - on Home, in the
  results panel, in History, and on the completion notification. A channel's
  name is sanitised before it becomes a folder, so a name the filesystem would
  reject, a name of nothing but dots, or an over-long name still works. A
  History entry's channel name opens that channel's folder and shows how many
  files from that channel have been downloaded, so a batch can be checked
  against what actually arrived. History now opens with one card per channel -
  file count, total size, and an Open folder button - ordered by the channel last
  downloaded from, with the size shown as a floor when Telegram withheld it.
- Android: files left behind by an earlier build in the old
  Download/SmartTG/<channel>/<type>/ tree are moved into the per-channel layout
  on first launch, and history entries are repointed at their new location so
  Open still works. Nothing is lost or duplicated: each file is copied, verified
  and only then removed, and a pass that could not finish is retried next launch.
- Android: Download ZIP beside Start download. The same selection is fetched and
  handed over as a single archive in the channel's own folder instead of as
  separate files. Files are fetched first and the archive written in one pass, so
  a file that cannot be fetched is skipped and reported rather than leaving a
  half-built archive; entry names are made safe to extract and duplicates are
  numbered. The request is persisted, so an interrupted archive is rebuilt on the
  next launch from TDLib's cache. An "Also keep the separate files" switch beside
  the button keeps the individual files as well (off by default, remembered, and
  recorded on the request so a queued archive still does what it was asked to do);
  a failed archive then says the files it already saved are still on the device.
  A finished archive is recorded in History as its own kind of entry - a ZIP icon,
  the word ZIP in place of a type, an Open action and no Re-download, since an
  archive was built on the device and has no Telegram message to fetch again. Its
  history entry is written only once the archive is on disk and is filed under the
  type it packed, or under All when it mixed types, so the type filter still finds
  it. Archives are not counted by the per-channel cards: they hold the same files
  those cards count.
- Android: a "Don't ask again" box in the analyze dialog, so a repeat user answers
  the file-type question once. The type becomes the remembered one and Analyze
  scans for it straight away, with the step naming the type it is using and a
  Change type action beside the button. The question comes back by unticking the
  box or from the new "Ask which type before analyzing" switch in Settings, which
  sits beside the sentence naming the type a skipped question will use, so the
  answer is both visible and reversible. A remembered type this build does not
  recognise falls back to All rather than being handed to the scan, where it
  would match nothing and report an empty channel for what is really a stale
  setting.
- Android: a menu on every screen after sign-in, listing the whole app - Home and
  History first, then each Settings group as its own entry - so any part of the
  app is one tap away from anywhere, with Sign out as its last entry below a
  divider. The drawer names itself with a pane title
  for screen readers, its rows carry labels instead of described icons, and it is
  disabled on the intro and login screens, where there is nothing behind it to
  navigate to. The group a Settings screen is showing is held by the shell, so
  the menu cannot mark the wrong entry as current, and Settings keeps a single
  back-stack entry whichever group it shows.
- Android: Settings is split into six groups - Account, Appearance, Analysis,
  Downloads, Channels, Updates - shown one at a time behind a row of section
  chips, instead of one long column that could only be read by scrolling through
  it. Each group opens with its own heading and a line saying what it covers, the
  heading is announced when a group is chosen, and the section chips are spoken
  as tabs rather than as radio choices, since they switch the content below them.
- Android: unit tests for the Settings section lookup - each key opening its own
  group, an unknown, missing or blank key falling back to the default, whitespace
  tolerance, and the invariants the keys themselves have to keep (unique,
  non-blank, no spaces, and a default that is a real section) - and for the rule
  that decides when an empty scan is one a different file type could fix, and for
  the rule that words and gates the deeper-search action - each ladder step naming
  the next limit rather than the one in force, the last step promising no number,
  and no action at all once the ladder has run out; and for setting one channel's
  limit - which limits a channel is offered, including one that is not on the
  ladder, how each choice reads, that the limit in force is always among them, and
  that re-choosing it writes nothing and leaves the channel's last-used stamp
  untouched so its row cannot move while it is being edited.
- Android: the results panel's empty state offers one Change type action when a
  scan found nothing of the type asked for but the walk did pass over other media.
  It reopens the Analyze question rather than showing a list of types in the
  panel, so the type is still chosen in one place and the panel holds no second
  copy of it; it is offered only when a type change could find something, so an
  All scan never suggests one. A walk cut short by the channel's scan limit gets
  a Search deeper action in the same place, so the empty card's advice names a
  control that is actually on the screen.

[CHANGED]
- Android: the permission screen is gone. Downloads are published through
  MediaStore into Download/SmartTG Downloader/<channel>/ without any storage
  permission on Android 10+; Android 8-9 request the legacy grant once and
  fall back to app storage when it is declined. The folder is now named after
  the app and holds one folder per channel, with no type level: earlier 2.2.0
  dev builds used Download/SmartTG/<channel>/<category>/, and files already
  there are left where they are.
- Android: analysis scans only the file type you choose, and which type that is
  is asked in a dialog when Analyze is pressed: All / Audio / Video / Images /
  Docs, the same set History's filter uses, with All meaning every file in the
  link. The scan then looks for that type alone, so a large channel is no longer
  trawled for media nobody asked for. That question is also the only place the
  type is set: the results panel has no type control, so a scan is never re-typed
  from the list it just produced, and with the question turned off Change type
  beside the Analyze button is what reopens it.
- Android: the results panel states what it found and asks what to take
  ("N files found - download all, or select a range?"), then shows the selected
  count and total download size before Start download.
- Android: one filter list everywhere, so no screen invents a type the others do
  not know about; History no longer adds a chip per channel.
- Android: the debug APK no longer ships emulator or 32-bit x86 natives and
  stores its ARM natives compressed - 81.2 MB before, about 38 MB now, or
  ~22.9 MB with -PminifyDebug=true. Still a single universal APK, not split.
- Android: the download panel's range selection is now one combobox - Newest 10 /
  20 / 50 / 100 files, or Custom range... for a first and last file number - in
  place of preset buttons, two number fields and a separate apply button. The
  control names the range currently in force, clamped onto the list on screen by
  the same rule the fields pre-fill from, so the value it shows and the range it
  gives cannot disagree. A preset larger than the list is disabled rather than
  silently clamped, so an entry never claims more than it does.
- Android: the light and dark schemes now set the container roles explicitly
  (surfaceVariant, surfaceContainer*, onSurfaceVariant, outlineVariant). Only
  background and surface were set before, so everything drawn in a container tone
  - filled cards, menus, the bottom sheet - fell back to the stock neutral greys
  and sat on the navy background looking like they came from a different app.
  Material You still overrides the whole scheme when Use wallpaper colors is on.
- Android: logging out now asks first, naming what is kept (downloads and
  history) and what is needed to sign back in, instead of ending the session on
  the first tap of a button in a scrolling list. It also moved: Sign out is the
  last entry in the menu, reachable from every screen, with the one confirmation
  dialog behind it and the Account group left informational. The login screen now
  replaces the app's screens on the back stack rather than stacking on top of
  them, so Back after signing out leaves the app instead of returning to a Home
  screen whose Telegram calls can only fail. Forgetting every channel's
  preferences is coloured as the destructive action it is, matching Clear
  history - both remove something the user cannot get back, and only one of them
  looked like it.
- Android: one app name and one content margin. The app is Smart TG Downloader
  everywhere it names itself; Home said "TG Downloader", and History's heading
  said "Download history" while its tab and menu entry said "History". Home,
  History and Settings now share a 16dp content margin (Home had 24dp, which read
  as one of the three being wrong rather than as a deliberate difference),
  buttons that stand alone are full width, the bottom bar's icons are no longer
  described on top of their own labels, and the results sheet is numbered as the
  third step of the flow its headings describe.

[FIXED]
- Android: a large channel could report zero files, or a single file. The
  history walk treated a short or empty page as the end of the chat, but TDLib
  answers from the history it has loaded and back-fills the rest in the
  background. The walk now retries, drops the page-boundary message it used to
  collect twice, and marks a provably truncated scan as incomplete with a Scan
  again action instead of claiming the channel has no such files.
- Android: launching the app showed a blank screen. The Compose root shared its
  name with the Application class, so the content lambda constructed an
  Application object and composed nothing.
- Android: the OTP step was silent and could not be resent. It now announces
  "OTP sent successfully" once per request, and the resend button counts down
  Telegram's own cooldown in its label and state description.
- Android: the Get started screen read out "bullet, bullet, bullet" instead of
  the feature list; the bullet glyph is now decorative and carries no semantics.
- Android: a failed download could not be retried without redoing the analysis,
  and History offered no way to retry a failed entry.
- Android: three compiler warnings in the Telegram client, where TDLib's own
  TdException declares its message as non-null while the code still guarded it
  with fallbacks that could never run. The guards now cover the case that can
  actually arrive - a blank message - so an auth error carrying no text reports
  "Telegram error" rather than a sentence ending in a colon with nothing after
  it, and a blank message no longer reaches the screen as an empty error. The
  Android build now compiles warning-free.

Version: 2.0.0 / 8.8.0
Build/Version Code: 4 / 8.8.0 (Android 2.0.0 / Windows 8.8.0)
Release Date: September 11, 2026
========================================================================

SUMMARY OF CHANGES:
This release fixes a stale scan-cache bug on Windows and completely rebuilds
the Android client natively in Kotlin + Jetpack Compose, removing Flutter.

[ADDED]
- Native Android app: rebuilt from scratch in Kotlin with Jetpack Compose
  (Material 3), Coroutines/StateFlow architecture, and TDLib for Telegram.
- TDLib integration: prebuilt native distribution (all ABIs) downloaded and
  SHA-256-verified at build time - no NDK/CMake setup required.
- Android scan pipeline: link analysis with monotonic scan tokens so results
  from a previous link can never repopulate the results sheet.
- Telegram API credentials are now injected via gradle.properties / CI
  secrets instead of being embedded in source.

[FIXED]
- Windows stale scan cache: analyzing a second link could reuse the previous
  scan's cached results; pending_scan is now invalidated on every new scan,
  cancellation, and dialog close.
- Windows scan race: concurrent scans are arbitrated by scan tokens so an
  older scan can no longer overwrite or report for a newer request.
- Windows offline check now probes a Telegram host instead of api.github.com,
  so VPN/proxy users blocking GitHub are not falsely reported offline.
- Download progress dialog stop action now drops cached scan results.

[REMOVED]
- Flutter Android client (android_flutter/), including all Dart code, Flutter
  runner projects (linux/macos/web/windows), and pubspec-based dependencies.
- Windows MSIX packaging script's Flutter/dart-msix dependency chain.

[BUILD CHANGED - Windows]
- Dropped Nuitka (2.8.9) and numpy from the build toolchain: Nuitka was
  extremely heavy (long compiles, huge memory use, slow release pipeline).
- New lightweight pipeline: Cython compiles all app modules
  (utils/worker/ui) to native .pyd machine-code binaries, then PyInstaller
  packages a single-file exe. No readable .py source or .pyc bytecode for
  app modules ships in the released executable.

[VERIFICATION]
- Windows: Python syntax check clean on all modified modules.
- Windows: local build of dist/SmartTGDownloader.exe verified.
- Android: fresh Gradle project pinned to AGP 9.3.2 / Kotlin 2.4.20 /
  Compose BOM 2026.09.00 / Gradle 9.7.1 (assembleDebug and assembleRelease
  build successfully locally; Android release is deferred until testing).
